First Principles Studio · production notes

Films made in code

How every First Principles video is produced: no camera, no editing timeline, no stock footage. Each film is a set of text files and programs that a computer turns into an MP4. This page walks through it step by step, using the real files from How ChatGPT Actually Works and its Hindi version.

In one paragraph

We write a script as a text file, with every sentence tagged with a label. An open-source text-to-speech model reads each sentence aloud, and the program measures how long each one takes. That gives a timeline: the exact second every sentence starts. Then everything else follows that clock. The animation is code that draws each frame (30 per second) based on which sentence is playing. The music is synthesised from maths, with its big moments placed on the key sentences. Subtitles come straight from the script. Finally, a speech-recognition model listens to our own audio to check the pronunciation, and FFmpeg stitches picture and sound into the final video.

Steps 5, 6 and 7 all read the same timeline from step 4. That is why the picture, words and music stay in sync without anyone dragging clips around. When a history beat needs real film of the past, licence-checked archive footage plugs into the same clock (see below).

1story

Research and story

Everything starts with a question a normal viewer would ask ("how does ChatGPT actually work?"). The AI assistant (Claude) researches it from primary sources (the 2017 Attention Is All You Need paper, the GPT-3 paper, and so on), then builds the story in layers:

  • Chapters: the big ideas in the order a beginner needs them (the guessing game → words become numbers → context → attention → layers → training → assistant → mistakes → recap).
  • Beats: inside each chapter, one idea per beat, each with a concrete example from the viewer's life: "a cup of hot… chai", Sachin Tendulkar, a rishta website, a viva exam.
  • Hook and payoff: a question in the first 30 seconds, and a last line that answers it ("Attention, really, is all you need").
  • Fact-check: every number in the script (175 billion parameters, 300 billion tokens) is checked against its source and listed in the description.
The creator stays the editor: you pick the topic, approve the outline, and reject anything that doesn't feel right. In this channel, for example, the music went through eight rounds before the "Organ & Time" style was approved.
2script

The script is a text file with labels

The script is plain text, but every sentence has a short label in brackets. The labels are what the animation and music hook onto later. A scene starts with @, and a ~ number is the pause after a line.

narration.txtnarration_hi.txt
@ game lead=0.4 tail=0.6
- [a] Let's start with a game. I'll give you half a sentence, and you complete it. ~0.4
- [b] "A cup of hot..." ~1.6          # 1.6 s silence: the viewer guesses
- [c] You probably said tea. Or maybe coffee. ~0.4
- [d] Now try this one. "Sachin Tendulkar is a famous..." ~1.4
- [e] Cricketer! Easy. ~0.5

When a word is hard to pronounce, the line can carry a spoken version in braces: {…}. The subtitles show the written text, and the voice reads the braces.

3voice

The narration: an open-source voice model

The voice is Kokoro, an open-weights text-to-speech model (82 million parameters, Apache 2.0 licence) that runs on an ordinary CPU through ONNX Runtime. No cloud service, no per-minute cost.

  • One clip per line. Each sentence is synthesised separately and saved as its own WAV file. Changing one sentence only re-records that sentence.
  • A custom voice by blending. Kokoro voices are vectors, so they can be mixed. The channel's narrator is 65% of a Hindi male voice and 35% of an American male voice, which gives an Indian-English accent.
  • Pronunciation fixes. Words the model gets wrong are respelled before synthesis ("ChatGPT" → "Chat G.P.T."; for Hindi, "चैट जी पी टी"). A phonemizer (eSpeak NG) turns the text into sounds first, including Hindi.
  • Disclosure. It is a synthetic voice, and the description says so.

4clock

The timeline: one clock for everything

While recording, the program measures each clip and lays the lines end to end with their pauses. The result is a small file that says exactly when every scene and every line starts. This file is the heart of the system.

build/timeline.json
{ "id": "game", "start": 53.567, "dur": 30.6,
  "lines": [
    { "label": "a", "start": 0.4,  "end": 4.9 },
    { "label": "b", "start": 5.3,  "end": 6.6 },   // "A cup of hot..."
    { "label": "c", "start": 8.2,  "end": 10.9 },  // "You probably said tea."
    ...

Change the script, re-record, and the timeline updates itself. The animation, subtitles and music all move with it automatically. That is also how the Hindi film works. Hindi sentences run about 30% longer, so each Hindi line stores a stretch factor, and the animation inside that line slows down to match.

5frames

Animation, frame by frame

There is no animation software. Each scene is a JavaScript function that answers one question: "what should the screen look like at time t?" It draws shapes and text onto a 1920×1080 canvas (Node.js with Skia, through the @napi-rs/canvas library). The renderer calls it 30 times for every second of film.

// the "A cup of hot …" moment, simplified from scenes/a.mjs
function game(ctx, S) {
  // S.at('b', 0, 0.8) goes 0 → 1 over 0.8 s, starting when line [b] is spoken
  const show = S.at('b', 0, 0.8);
  text(ctx, 'A cup of hot', CX, CY, { size: 92, alpha: show });

  // the answer pops in exactly when the narrator says "tea" (line [c])
  const pop = S.at('c', 0, 0.6, E.outBack);
  text(ctx, 'tea', CX + 380, CY, { size: 92 * pop, color: YELLOW });
}

Because the scene asks for "when line c starts" rather than "at 61.8 seconds", it never goes out of sync, even after the script changes.

frame 96

Try it: this miniature is drawn the same way. Drag the slider and the function is called again for that frame number. Line [b] starts at frame 30, and line [c] ("tea") at frame 120.

  • A visual kit per film: the palette, fonts, the mascot "Tokku", icons, token chips and probability bars, all written once and reused in every scene.
  • Raw frames to video: each frame's pixels are piped straight into FFmpeg, which encodes H.264. Four workers each render a quarter of the film at the same time.
  • Scale: the 17½-minute Hindi film is 31,738 frames and took about 35 minutes to render on a 4-core machine. The scenes for this film are about 1,900 lines of code.
  • Languages: every word on screen is written as tr('English', 'हिंदी'), so one switch renders the Hindi version of every scene.

6words

Subtitles come from the script, not from listening

We already know every word and when each line is spoken, so subtitles need no speech recognition. Long lines are split at sentence breaks into cues of at most two lines, and two-line cues are balanced so no word sits alone on the second line. The renderer draws them into the frame (burned-in), and the same cues are saved as an .srt caption file for YouTube.

engine/audio/subtitles.pysubs.jsonsubtitles.srt
7sound

Music and sound effects, synthesised from maths

The background score is not made by an AI music generator and uses no samples or stock tracks, so there is nothing to license and no copyright claims. It is written as Python code (NumPy and SciPy) that builds every sound from waves:

  • Instruments as maths. A pipe organ is a sum of sine-wave harmonics (the "ranks" of an organ). A piano note is a quick attack with a decaying tone. Choir, strings and timpani are built the same way, and reverb is added by convolution, which simulates a large hall.
  • The score follows the timeline. Each scene is given a harmony and a level. New layers come in on chosen lines, and a climax (a timpani roll, full organ, choir) is placed so its downbeat lands exactly on the key sentence, for example "That's it. That's the whole trick."
  • Sound effects (pops when something appears, whooshes on chapter cards, a bell on the subscribe button) are placed on the same cue labels as the animation.
  • Mixing for clear speech. Whenever the narrator speaks, only the music's speech frequencies (500–4,500 Hz) dip, so the voice stays clear without the music disappearing. The final mix is set to −14 LUFS, YouTube's loudness standard.

8checks

Quality checks with a speech-recognition model

Here is where transcription comes in: not to make subtitles, but as a listening test. Whisper (OpenAI's open-source speech recognizer, MIT licence, run locally through faster-whisper) transcribes our own narration. If Whisper can't understand a word, a viewer probably can't either.

  • Pronunciation score. For every line, the transcript is compared with the script letter by letter (the character error rate). For the Hindi film, the 110 lines averaged 3–6%, and most of that was spelling differences.
  • Catching real problems. It found that "अटेंशन हेड्स" sounded like "addition hills" and "चैटजीपीटी" like "JGPT". Both were reworded or respelled, and the check was run again.
  • Choosing a voice. Four Hindi voices were tested the same way, and the clearest one won.
  • Picture and sound. Contact sheets show one frame from every line, to catch overlapping or untranslated text. Loudness is measured, and a few lines are transcribed from the final MP4 to prove the sound is in sync.
A machine check is a proxy. It catches unclear words, not a wrong tone of voice, so the creator still watches the film before publishing.
9deliver

Assemble, cut Shorts, make thumbnails

  • The film: FFmpeg joins the rendered picture and the final mix into an MP4, plus an .srt caption file.
  • Shorts: chosen line ranges are re-rendered and placed in a vertical 1080×1920 frame with a big title and subtitles. Each Short gets its own score that builds to a climax on its key line.
  • Thumbnails: drawn with the same visual kit, in two or three variants for YouTube's Test & compare.
  • Upload kit: title options, description with chapter times taken from the timeline, tags, pinned comment, quiz and settings.
  • Storage: everything lives in a Git repository. Full-quality masters are split into 95 MB pieces on a separate branch, with join scripts to rebuild them.
+archive

Real footage from the past, licence-checked

Some beats are about things that really happened and were filmed: an operator at IBM's SAGE air-defence computer in 1956, a 1950s power station, a bank's ledger room. For those, real film beats any drawing. A script searches archive.org for it and pulls it into the scene on the same clock as everything else.

  • Where it looks. The Prelinger Archives (US corporate, educational and industrial films, 1930s–80s), FedFlix (US government films), NASA, and 78rpm records for the sound of a period.
  • A licence check before anything is used. Not everything on archive.org is free to use. Only about 1,900 of the 10,500 Prelinger films carry a public-domain dedication, and the 78rpm collection is for research only. In the US, recordings become public domain 100 years after they were published, so only those from 1925 or earlier qualify. Every item gets a verdict:
VerdictMeansUsed?
Greenthe item itself is dedicated to the public domainyes
Amberpublic domain by its collection's statement or by its date (a 1919 march)only after a written check, which is recorded
Redanything else, including most Prelinger titlesonly with a licence we hold

  • Only the seconds needed are downloaded, and the original soundtrack is removed (an old public-domain film can still contain copyrighted music).
  • Every shot is credited on screen, e.g. "Archive footage: On Guard! The Story of SAGE (1956) · Prelinger Archives · public domain". Film from 1956 must never read as today, and American footage is never passed off as India.
  • Period music is a moment, not the score: a gramophone in a 1920s scene, under the channel's own music.

The craft playbook

Code makes a film possible; craft makes it worth watching. These rules come from our own films and from nine open-source motion-design guides written for AI coding assistants (credited below). Each outside idea is checked before it is adopted: does it work, is it legal, does it fit the channel?

Story

One core message per film, one new thing to know per scene. A hook in the first two seconds. A recurring device, and one moment where the idea is shown, not captioned. Where it can, the explanation is a recognisable machine, with a window cut into the part doing the work.

Time for the viewer

One thing to take in at a time. Text stays on screen at least 1.2 seconds per 8 words. Fast actions, held meanings.

Motion

Nothing moves in a straight line at constant speed. One thing that matters moves at a time. Characters anticipate, overlap and never move in unison.

Sound

Every visual event has a sound and every sound has a reason, landing a couple of frames before the picture. Not every cut gets a whoosh.

Honesty

Every fact shows its source, invented numbers say "illustrative", imagined frames say "imagined", archive film shows its year. Every number in a scene comes from one model of the real thing, and sped-up or slowed time carries a badge (×4, ×1/20).

Review

Judge the frames, not the code: contact sheets, frame strips, full-size crops. Then the creator watches the whole film before it is published.

The whole procedure is saved as a Claude Code skill, make-film: Director → Art Director → Animator → Render Engineer → an independent Critic → local repair → delivery. The creator approves the story and the look before any animation code is written. The Critic works from the rendered frames, not the builder's description, and reports each defect with its frame number and the smallest fix. A fix gets at most two attempts before the agent stops and asks. Any mistake that recurs becomes a new rule, so the next film inherits the fix.

If you want to try this yourself

Start small. The whole idea fits in five steps, and each one can be a short script:

1 · Script with labels

Write 10 sentences in a text file, one per line, each with a label.

2 · Voice + timeline

Run a TTS model on each line. Measure each clip and write down when each line starts.

3 · One scene function

Write a function that draws a frame for time t, using "seconds since line X started".

4 · Frames to video

Call it 30 times per second and pipe the frames into FFmpeg.

5 · Music on cues

Start with a simple pad, and add one swell on your most important line.

The rest (Shorts, translation, thumbnails, quality checks) is the same idea reused: one clock, and everything else follows it.
